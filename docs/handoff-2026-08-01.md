## Decisions already made — do not reopen without a reason

- **Per-seat discard trays stay.** A central pool is a *fallback*, wanted because
  the middle of the board is mostly empty, not a replacement that was agreed.
- **換三張 is off by default** and host-opt-in. It is not in Novikov's ruleset.
- **Freed horizontal space went to the hand, not to bigger tray tiles.** The hand
  was 19.1px wide against a ~24px readability floor and it is the only thing a
  player taps.
- **Tiles are flush with a bottom bevel.** Fully flat read as a printed sheet;
  the left/right/top bevels were the ones that doubled up between neighbours.
- **Singletons keep the 3D art** — the well's last discard, the long-press
  preview, the first-discard flip panel.
- **Each flat cell paints its own face**, rather than sharing one surface across a
  run: a lifted hand tile over a shared surface reads as a hole in the strip.

## Open — needs a decision, nothing started

Also recorded as O1–O4 in
[ARCHITECTURE.md §12](../ARCHITECTURE.md#12-open-questions--explicit-deferrals).

**O1. The release binary embeds the tile SVGs, which ARCHITECTURE §13 forbids.**
`scripts/release/gen-embedded-client.mjs` walks `packages/client/dist` and
base64-embeds every file into `embedded-client.ts`, compiled into the Bun binary —
57 SVGs. §13 says the CC-BY-SA boundary depends on those staying "standalone
fetched assets" and not being merged "into compiled JavaScript output". Both cannot
be true. Predates the flat set (the embed is A20) but that set doubled the count.
A licensing call, not a patch: exclude `tiles/` from the embed and ship them beside
the binary, or accept the merge and state the binary's licence. **npm package and
from-source are unaffected** — both serve `tiles/` from disk.

**O2. Bot pacing.** Bots resolve a circuit faster than a player can follow. The
user asked for "play history or slow them down a little bit". My recommendation was
both: a per-move delay as a server config value (tunable, not a magic number) plus a
scrollable history panel. The event feed keeps only the latest line and drops to one
line on short viewports *by design* (R1), so nothing recovers a move you looked away
for. **Not yet chosen.**

**O3. Central discard pool.** Show every discard in the middle, mark the last one,
and show each player's chosen void suit. The redaction decision it needs:
`PublicPlayer` has no `voidedSuit` — only `you` gets it, and the first discard is
face down precisely so the suit is not leaked early (A37). Reveal it only once that
player flips their first discard, which is when a real table learns it. Note the PDF
edge case: a player may declare a suit they hold none of, in which case a
card-indicator stands in and no tile ever reveals it.

**O4. Discard tile styling.** The user said "the tile styling doesn't fit the
discard pile". My reading is that a flush run reads as tiles *held together*, right
for a hand or meld and wrong for thrown-away tiles; my recommendation was standalone
3D tiles for discards, keeping flush for hands and melds. **The user has not
confirmed what specifically looks wrong** — ask before rebuilding it, since either
direction is real rework.

Also carried forward, lower priority: the own melds row in `OwnZone` is a
non-wrapping `flex` of fixed-width tiles, so three or four melds overflow
horizontally and the root's `overflow-x-hidden` clips them — it wants the same
scroller `OpponentTop` got. And side opponents render no melds at all, so a player
who has ponged shows a small hand with no visible reason; R7 bought roughly the
height that would need.

## Traps that cost time this session

- **Restart the server after any client rebuild.** `@fastify/static` is registered
  with `wildcard: false`, so the asset list is snapshotted at boot. A rebuilt bundle
  404s into the SPA fallback and the page dies with a MIME-type error on a
  `text/html` module script.
- **`pnpm e2e` needs port 8080 free.** Playwright starts its own server with
  `reuseExistingServer: false`; a locally-running server makes the whole suite fail
  before the first test.
- **`VITE_E2E=1` builds are for tests only.** They attach `window.__e2e`; specs fail
  without them. Rebuild *without* it before handing the app to a human.
- **The specs' game is random and unseeded.** `room.ts` uses `randomUUID()`, so a
  local pass proves little — R6 passed locally every time while failing CI three
  times running. Prove layout claims with an injected-spacer probe or a forced
  state, not a lucky round.
- **Playwright's `devices['iPhone SE']` is 320×568, not 375×568.** The whole R6 bug
  was the audit's numbers being measured at 375 while CI asserted at 320.
- **A wrapping flex container defaults to `align-content: stretch`.** Spare
  cross-axis space is handed to the lines and children are drawn *past their aspect
  ratio*. This is what made the side trays' tiles "way too long". `content-start
  items-start` plus `min-h-0` and no `flex-1`.
- **`svg.getBBox()` must be called on the root.** Per-element boxes are in that
  element's own space, and the pin dots sit inside nested transformed groups — one
  measurement pass put pin-1's box 1300 units from every other tile's.
- **The screenshot script could ship the wrong screen.** It used to shoot after its
  play loop, so a bot winning inside 14 moves produced a round-end image in
  `screenshot.png`. Fixed, and it now fails rather than shipping the wrong screen —
  but it is still an unseeded random game, so *look at the output*.
