## Findings

### A81 — `pnpm audit` not in CI (process · **medium**)

**Claim:** `pnpm audit` is run nowhere in CI. A77 found ten production
vulnerabilities because it had never been run; the command was added to
CLAUDE.md's dev-commands section but not wired into `.github/workflows/ci.yml`.

**Current state:** 7 dev-dependency advisories (4 high, 3 moderate) across
`vite`, `nanoid`, `postcss`, and `qs` (via Stryker). Zero production
vulnerabilities (`pnpm audit --prod` is clean). The dev advisories are all
transitive via `@vitest/coverage-v8 → vitest → vite → postcss → nanoid` and
`@stryker-mutator/core → typed-rest-client → qs`.

**Fix:** Add a `pnpm audit --prod` step to CI (prod-only so dev transitive
churn doesn't gate deploys). Bump `vite` from 8.0.13 → 8.2.x to clear the
four high advisories on the dev side.

### A82 — Tailwind class selectors in e2e specs (process · **medium**)

**Claim:** CLAUDE.md says "Never put a Tailwind class in an e2e selector" and
documents that twelve `data-` hooks exist for this reason. Three selectors in
`e2e/` use Tailwind classes:

- `e2e/house-rules.spec.ts:56` — `div.flex.flex-wrap img[alt]`
- `e2e/ui-clicks.spec.ts:55` — `div.flex.flex-wrap img[alt]`
- `e2e/ui-clicks.spec.ts:77` — `div.flex.gap-3 > button`

A class rename (e.g. from the recent visual-system sweep) would silently break
these selectors — the test would find nothing and either pass vacuously or time
out, never naming the cause.

**Fix:** Add `data-hand-tiles` to the hand container and `data-void-choices`
to the void-suit button row; replace the three selectors.

### A87 — `declareHuOnDraw` offered after a pung into a complete hand (bug · **high**)

**Claim:** `computeLegalActions` in `views.ts` checks `isWinningHand` but not
`state.drewThisTurn` before offering `declareHuOnDraw`. After a pung (which is
not a draw), if the 11 standing tiles plus the new meld make a winning hand,
the legal-action list includes `declareHuOnDraw`. The engine correctly rejects
it (`must_draw_first`), but all three bot difficulty levels pick it because it
is in the legal list. The rejection path in `room.ts` logs a warning and
returns without calling `scheduleNext`, and `botPendingSeats` has already been
cleared — so nothing is left scheduled and the room stalls dead.

**Repro:** A bot pungs the last tile it needs for a complete hand. The
resulting 11 tiles + 1 meld form a winning shape. The bot sees
`declareHuOnDraw` in its legal actions and picks it. The engine rejects it.
The room silently stops advancing.

**Fix:** Added `state.drewThisTurn` guard to the `declareHuOnDraw` branch in
`computeLegalActions`. The action is no longer advertised after a pung, so bots
pick a discard instead and the round continues. Found by the untracked scratch
test `zz-audit-scratch.test.ts`.

## Checked and clean

These areas were examined and found correct:

- **Engine determinism.** `Date.now()` appears only as a defaulted trailing
  parameter in `applyAction` and `createGame`, per the convention. No
  `Math.random`, `crypto`, or non-deterministic iteration anywhere in the
  engine package.

- **View redaction.** Every `GameState` field was traced through `projectView`,
  `toPublicPlayer`, and `redactEventsFor`. Concealed kongs, drawn tiles, void
  declarations, the first-discard tile, and the winner's hand shape are all
  correctly redacted per viewer. Spectator views expose no concealed hands.
  `yourLegalActions` is computed only for the viewer's own seat. No new fields
  have been added since A58.

- **WS boundary validation.** `ws.ts` validates message shape, whitelists
  client-issuable action types (`CLIENT_ACTION_TYPES`), checks seat identity,
  and gates host-only commands on seat 0. `handleAction` in `room.ts` guards
  on `ended`, validates shape, and rejects non-client action types. The
  `claimWindowExpire` and `draw` actions are server-only.

- **Security headers.** CSP, referrer-policy, X-Frame-Options, HSTS (on
  HTTPS), nosniff all set. Origin check on WebSocket upgrade. Rate limiting
  on lobby creation and join attempts. Concurrent-games ceiling. Frame-size
  limit tested.

- **Clone correctness.** `clone()` in `actions.ts` does not clone `wall`,
  which is correct: the wall array is never mutated after creation (verified:
  no splice/push/pop/sort/assignment on `wall[]` anywhere in the engine).

- **Scoring.** `COMPATIBILITY` table matches PDF Table 9 including the A67
  corrections. `calcHandScore` correctly handles Win-after-Kong + Under-the-Sea
  stacking. `calcTMV` correctly excludes Kong fan. Root counting handles both
  standard and seven-pairs shapes. Fan cap is applied as `Math.min(total,
  fanCap)` with `handValue = 2 ** totalFan`.

- **Claims.** Hu priority over pung/kong, CCW-nearest tiebreak, already-Hu
  seats auto-passed, void-suit tiles refused for all three claim kinds,
  furiten skip-Hu rule with greater-value override — all correct.

- **Room lifecycle.** `teardownTimers` clears all pending timers. `endMatch`
  closes sockets and deletes the room. `clearPendingBotWork` resets
  `botPendingSeats`. The A68 stale-decision fix is in place (the bot claim
  callback re-enters `scheduleNext` when it finds the window gone). The A9
  once-only `roundEndBroadcast` guard is correct.

- **Persistence.** `validateRoomSnapshot` derives the field list from a fresh
  game (self-maintaining). The code-column-authoritative rule is enforced.
  `loadLiveRooms` parses per-row. The `ledger` default is safe.

- **Bot logic.** `kongWorthTaking` skips void-suit kongs for all three levels.
  `mustPlayVoidFirst` is called by the easy bot; medium/hard inherit it
  through their discard selection paths. The bot ladder test asserts ordering.
  `shanten.ts` handles kong-expanded hands.

- **Client store.** The A70 `closed` guard is on both `onmessage` and
  `onclose`. Reconnect backoff and `MAX_RETRIES` are correct. `countedRounds`
  prevents double-counting on replayed `roundEnd`. `resetSession` cleans all
  state. `connectGame` tears down prior connections.

- **Service worker.** Network-first for navigations (shell stays fresh).
  Cache-first only for content-hashed `/assets/` and the stable art. Version
  bump documented next to the list. `skipWaiting` + `clients.claim` on
  activate.

- **i18n.** Six catalogs, parity test exists (`lang.test.ts`), every test loop
  derives from `LANGS`. No hard-coded English strings found in TSX (all use
  `t()` calls). The four coined Japanese terms documented in TODO.md.

- **Accessibility.** `aria-modal` backed by `useDialogFocus` on all three
  dialogs. `aria-live="polite"` on the claim bar and event feed. `prefers-
  reduced-motion` handled in CSS (collapses all animations) and by Framer's
  `MotionConfig`. `noAutofocus` exceptions documented with biome-ignore.

- **CSS/layout.** Tile lap geometry consistent. Side-river wrap directions
  correct per CLAUDE.md invariants. `prefers-reduced-motion` rule present.
  All colors use CSS custom properties (no raw hex outside token definitions).
  No `100vh` usage (no mobile Safari viewport issue).

- **TypeScript strictness.** `strict: true`, `exactOptionalPropertyTypes`,
  `noUncheckedIndexedAccess`, `noUnusedLocals`, `noUnusedParameters` all
  enabled in `tsconfig.base.json`.

- **Memo/perf.** `OwnZone`'s `useCallback` keys on seat numbers, not `view`.
  `HandTile` is memo'd. `tileTap` uses a stable ref trampoline. `Game.tsx`'s
  `openPile` callbacks key on the seat constant. No inline closures found
  passed as props to memo'd components in the hot path.

## Improvement ideas (not defects)

1. **Add `pnpm audit --prod` to CI** (A81) — one line, immediate value,
   prevents a repeat of A77.

2. **Bump `vite` to 8.2.x** — clears 4 high dev advisories, low risk

3. **Replace the three Tailwind e2e selectors** (A82) — small change, removes
   a documented class of silent breakage.

   define a light palette today. A `prefers-color-scheme: dark` block
   redefining the tokens would land it with no component changes.

   issues before they reach the remote.
